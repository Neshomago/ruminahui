# Rumiñahui — Action Game Project

Narrative and design documentation for an action-adventure game about Rumiñahui, built as reference material for AI-assisted Unity development (starting with code/systems, generic placeholder assets, real art to follow later).

> **📍 Current status and how to continue → [PROGRESS.md](PROGRESS.md)**
> All systems and all 26 missions are coded on branch `feature/systems-build`. They're verified offline but not yet opened in Unity. Start there on any machine or with any AI tool.

## Repo structure

```
/docs                     ← all design documents (this package) — the source of truth
/Assets                   ← Unity project assets
  /Scripts                ← all game code (namespace Ruminahui)
  /Tests/EditMode         ← unit tests
  /Resources/Dialogue     ← dialogue data generated from docs/04 (don't hand-edit)
  /Prefabs/Placeholder
  /Scenes                 ← generated by the Rumiñahui ▸ 2. Build Scenes menu
/Packages/manifest.json   ← Unity packages (URP, Cinemachine 3, Input System, Addressables…)
/Tools/CompileCheck       ← offline compile + test harness (no Unity needed)
/Tools/DialogueImport     ← docs/04 → dialogue JSON importer
/PROGRESS.md              ← status, how to resume, next-step checklists — update every session
/AI_BUILD_PROMPT.md       ← the original build brief for the coding AI
/IMPLEMENTATION_LOG.md    ← maintained BY the coding AI: what was built, which doc governs it, assumptions
/LESSONS_LEARNED.md       ← mistakes + prevention rules — read before working
/UNITY_SETUP.md           ← open in Unity, menu steps, what to test, Unity-only hooks
```

## How to use this repo

1. Initialize this as a git repo (`git init`) and commit `/docs` first, as the project's source of truth.
2. Hand `AI_BUILD_PROMPT.md` to your coding AI (Claude Code or similar) to begin implementation. **To continue existing work, use the resume prompt in [PROGRESS.md](PROGRESS.md) §2 instead.**
3. As the AI builds, it should maintain `IMPLEMENTATION_LOG.md` at the repo root — a running record of what was built, which doc/section drove each decision, and any assumptions made where the docs didn't specify something. **This log is what makes future edits safe**: before changing any system, check the log entry for it to see which doc governs that feature and update the doc and the code together.
4. Real art/audio assets get swapped in later using `10-asset-list.md` as the production checklist and `07-world-bible.md` / `09-myth-ambiguity-direction.md` as direction — none of that blocks starting the code now.
